## SF 评测失败定位

作业运行于 `atl1-1-01-002-16-0`，申请 1 张 A100、8 CPU、96 GB 主机内存。冻结 manifest 校验和运行库复制阶段均返回成功，但策略服务随即退出：

```text
File ".../src/sf_followup/evaluation.py", line 136, in server
    import torch
File "/tmp/vla-recovery-eval-3571051-14230444/site/torch/__init__.py", line 409
    from torch._C import *
ImportError: libcusparseLt.so.0: cannot open shared object file: No such file or directory
```

父进程的 `Policy startup failed; see server log` 是上述导入错误的外层提示。启动顺序表明错误发生在 checkpoint 读取、模型构建及 rollout 之前。`workers/` 只有 server 日志，没有策略 metadata 或 episode journal；有效评测记录为零。

**直接原因：** `src/sf_recovery/stage.py::stage_runtime` 仅遍历 `('torch', 'nvidia')`。当前安装的 PyTorch 2.7.1+cu126 使用位于 `site-packages/cusparselt/lib/` 的同级包，源库文件存在，大小为 237,384,129 bytes，但没有复制到节点本地目录。`readelf` 确认 `libtorch_cuda.so` 的 `NEEDED` 包含 `libcusparseLt.so.0`，RPATH 包含 `$ORIGIN/../../cusparselt/lib`；复制后该相对位置缺失。

因此“Node-local PyTorch/CUDA runtime staged”只说明现有文件清单复制完成，没有验证动态依赖闭包。此前 CPU 单元检查和 checkpoint 恢复验证未覆盖该节点本地 CUDA 导入路径，不能视为这一启动路径已通过验证。
